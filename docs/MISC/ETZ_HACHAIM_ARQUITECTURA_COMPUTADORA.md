## 🎼 SUCESIVO vs SIMULTÁNEO en Arquitectura

### SUCESIVO (Lenguaje = Cinta de Cassette)
```
Tiempo: t₀ → t₁ → t₂ → t₃ ...
Procesamiento: token[0] → token[1] → token[2] → ...
Módulo: HiloEscucha → NLU → OrquestadorHerramientas → HiloHabla
Característica: SECUENCIAL, LÍNEAL, DETERMINISTA
```
- **Usuario habla** → *transcripción* (Hod = lenguaje)
- **NLU procesa** → *comprensión contextual* (Tiféret = yo)
- **Cerebro razona** → *respuesta generada* (Binah = razón)
- **TTS habla** → *audio saliente* (Netzaj = creatividad auditiva)

### SIMULTÁNEO (Pensamiento = Orquesta Sinfónica)
```
Tiempo: {múltiples contextos activos en PARALELO}
Procesamiento: 
  - Monitoreo del sistema (proactividad)
  - Ciclo circadiano (ritmo biológico)
  - Detector de anomalías (vigilancia)
  - Emoción + contexto (Dmut)
  - Memoria de procedimientos (habilidades)
Módulo: MotorProactividad ⥇ CicloCircadiano ⥇ Detector ⥇ Memoria
Característica: PARALELO, HOLÍSTICO, CONTEXTUAL
```
- **Mientras escucha**, el sistema ya está:
  - Monitoreando CPU/RAM (habilidades/monitor_sistema)
  - Calculando proactividad (núcleo/proactividad)
  - Evaluando ciclo circadiano (núcleo/ciclo_circadiano)
  - Detectando anomalías (núcleo/detector_yikavu)

## 🔄 TZIMTZUM (Contracción/Retiro Inteligente)

### ¿CUÁNDO hacer Tzimtzum?

**HACER Tzimtzum:**
- ⚠️ Aplicaciones pesadas detectadas (Ableton, Maya, Blender, Videojuegos)
  - CPU > 70% durante > 60 segundos
  - GPU activa (NVIDIA/AMD)
  - Latencia de audio crítica
- ⚠️ Usuario está en modo "no molestar" explícito
- ⚠️ Batería < 20% y apps pesadas ejecutándose

**NO HACER Tzimtzum:**
- ✅ Navegador ligero (Chrome, Edge en pestaña individual)
- ✅ Editor de código (VS Code)
- ✅ Aplicaciones de productividad (Word, Excel)
- ✅ Aunque esté en "monitor todo" - diferenciación inteligente

**Algoritmo Tzimtzum Inteligente:**
```python
def should_tzimtzum() -> bool:
    cpu_load = obtener_cpu_load()
    gpu_load = obtener_gpu_load()  # si NVIDIA
    
    if cpu_load > 70 and gpu_load > 50:
        # Aplicación pesada + GPU = Gaming/3D rendering
        return True
    elif cpu_load > 80 and tiempo_sostenido > 60:
        # CPU crushed durante > 60s = Video encoding/Compilación
        return True
    elif "ollama" in procesos or "llm_studio" in procesos:
        # Si NUESTRO LLM corre, no hacer Tzimtzum (es parte del sistema)
        return False
    elif "chrome" in procesos and num_tabs > 1:
        # Navegador con múltiples tabs = ligero, monitorear
        return False
    else:
        # Default: NO Tzimtzum, monitorear todo
        return False
```

class CamaraVidencia:

## 🔊 DIAGNÓSTICO MEJORADO: MICRÓFONO + VAD + LATENCIA

### Problema Actual: "Tiene acceso pero no reacciona"

**Hipótesis**: Wake word detection falla (no Silero VAD, sino MATCHING)

**Solución**:
1. Verificar que micrófono CAPTURA audio
2. Ejecutar VAD (Silero) con threshold correcto
3. Detectar WAKE WORD: "COMPUTADORA" o "EMET"
4. Si no detecta, LOGUEAR el audio para debugging

```python
# computadora/voz/diagnostico_microfono.py (nuevo)
def diagnosticar_microfono():
    """Verifica capturas completo de micrófono."""
    
    # Paso 1: Lista dispositivos
    dispositivos = sd.query_devices()
    logger.info(f"Dispositivos: {dispositivos}")
    
    # Paso 2: Prueba captura 3s
    audio = sd.rec(int(3 * 16000), 16000, 1)
    sd.wait()
    
    # Paso 3: Whisper transcribe
    resultado = whisper.transcribe(audio)
    logger.info(f"Captura transcrita: {resultado}")
    
    # Paso 4: Wake word match
    if re.search(_WAKE_WORD_RE, resultado):
        logger.info("✓ Wake word DETECTADO")
    else:
        logger.warning("✗ Wake word NO detectado - audio sí capturado")
    
    return resultado
```
